AI agents

Your agent on your clusters, without your kubeconfig

Connect Claude Code, Cursor or any MCP client to kubelatch. It acts as you with only the permissions you choose, for a few hours; its writes can wait for your approval; every call is in the audit; and you cut it off with one click.

Connect your agent How it works

// the problem

Two bad options.

You're developer on shop and you ask your agent “find out why the web pod is failing”. Give it your kubeconfig, and it can do everything you can while the audit shows only you. Or ask an administrator for a bot and wait, which nobody does for a ten-minute task.

// delegated, in six steps

Like “Sign in with Google”, for your clusters.

You don't hand over your password: you give a limited permission you can take back.

  1. Add kubelatch once

    claude mcp add --transport http kubelatch https://kubelatch.example.com/mcp

  2. Your browser opens

    The first time the agent uses it, on kubelatch, where you're already signed in.

  3. You choose, and authorize

    “Claude Code wants to access your clusters”: your permissions, read-only, for 8 hours.

  4. It reads, it doesn't break

    Pods, logs, events. A read-only session isn't even offered the tools that change things; if it needs more, it asks with request_access.

  5. Changes wait for you

    Give it your developer role with “Writes need my approval”, and every change it wants waits for you, with the diff.

  6. It ends by itself

    After 8 hours. Before that, Cut.

Connect it in one line

claude mcp add --transport http kubelatch https://kubelatch.example.com/mcp

The first time it uses kubelatch, your browser asks what it may do: your permissions, read-only by default, for 8 hours. Cursor and any MCP client connect the same way, and Claude Code has a plugin that also stops it reaching for kubectl.

// bot or delegated

Two identities that never mix.

You're developer on shop. Your Claude Code, delegated, works as you, read-only. Meanwhile the on-call agent that reviews alerts at night uses the bot ops-agent, viewer on every namespace because an administrator granted it.

// how much it bothers you

Once per session, and only when it writes.

  • The browser opens once per session, like kubelatch login.
  • Read-only work asks nothing.
  • For a task with several changes, one approval of “developer on shop, 30 minutes” instead of one per change.

kubelatch states its limits: what an agent does through another way into the cluster, and what it does with what it reads. What it does not cover

Stop messing with Kubernetes credentials.
